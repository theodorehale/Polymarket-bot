## Accounting and interpretation

The baseline linear fee assumption is not current fee validation. The new offline fee accounting uses explicit market/token/time-bound schedule evidence and the documented share-price fee curve per depth level. It conservatively rounds costs upward, assumes no rebates, includes entry and exit fees, and refuses an incompletely closed position. This remains paper cashflow, not real revenue. A source URL and fee schedule supplied to a pure function are an evidence contract; the function cannot authenticate a caller's claims. Reports must retain the original fetched payload and hash.

### Reproduce

Run npm ci, npm run build, npm run microstructure:validate, then npm run microstructure:replay. The replay verifies hashes and overwrites paper-report.json deterministically. npm run microstructure:collect captures only Polymarket public books in a new session directory; it does not claim to validate the original dual-feed hypothesis. The legacy RTDS collector is retained as historical code and is no longer the default entry point.

Still outstanding: paired permitted spot data for a separately identified hypothesis or authorized historical data for the original hypothesis; robust delta reconstruction; causal signal generation, inventory/position lifecycle and held-out multi-window evaluation. The explicit linear-fee simulator is a cost scenario only; verified curve-based accounting is used by the real-book diagnostic.
